# Версионирование документации в Antora с помощью веток

Antora собирает версии документации из веток или тегов Git.
В туториале используются ветки.
В отличие от тега, в ветку можно вносить исправления и после публикации версии.
Каждая ветка становится отдельной версией документации, и ее можно выбрать в переключателе версий на сайте.

Туториал — для технических писателей, которые только знакомятся с Antora и хотят освоить версионирование документации на практике.
Он описывает только работу с версиями.
Остальные возможности Antora описаны в [официальной документации Antora](https://docs.antora.org).

## Что вы соберете

В туториале используется вымышленный продукт Red Apple Conference, созданный по образцу реальной платформы.
Вы соберете сайт документации для одного из его компонентов, `docs-server`, с двумя версиями:

- версия 1.0 в ветке `v1.0`;
- версия 2.0 в ветке `v2.0`.

На сайте будет переключатель версий для перехода между ними.
Сайт собирается и открывается на вашем компьютере.
Аккаунт на хостинге и удаленный репозиторий не нужны.

## Что понадобится

- Node.js — версия с активной долгосрочной поддержкой (LTS).
- Git.
- Терминал.
  Команды из туториала без изменений работают в Bash, Zsh и PowerShell.
  Если Windows PowerShell сообщает, что выполнение сценариев отключено в этой системе, запускайте `npm.cmd` и `npx.cmd` вместо `npm` и `npx`.

## Подготовьте проект

Репозиторий документации и сборка Antora будут в одной директории.

1. Создайте репозиторий:

   ```shell
   mkdir docs-server
   cd docs-server
   git init -b main
   ```

2. Создайте файл `.gitignore`, чтобы Git не отслеживал результаты сборки и установленные пакеты:

   ```
   build/
   node_modules/
   ```

3. Установите Antora в эту директорию:

   ```shell
   npm init -y
   npm i -D -E antora
   ```

   Флаг `-y` принимает все значения по умолчанию.

   Вторая команда устанавливает Antora как зависимость для разработки (`-D`) и фиксирует точную версию (`-E`).

4. Проверьте установку:

   ```shell
   npx antora -v
   ```

   ```
   @antora/cli: 3.1.15
   @antora/site-generator: 3.1.15
   ```

   Номера версий у вас могут отличаться.

5. Сделайте коммит:

   ```shell
   git add .
   git commit -m "Set up the project"
   ```

## Создайте компонент документации

Компонент — единица документации в Antora: дерево директорий с дескриптором `antora.yml` и хотя бы одним модулем.
Файл `antora.yml` лежит в корне репозитория.

1. Создайте страницу `modules/user-guide/pages/index.adoc`:

   ```asciidoc
   = Server User Guide

   This page describes version 1.0 of the server.
   ```

2. Создайте файл навигации `modules/user-guide/nav.adoc`:

   ```asciidoc
   * xref:index.adoc[User guide]
   ```

3. В корне репозитория создайте `antora.yml`:

   ```yaml
   name: docs-server
   title: Server
   version: '1.0'
   nav:
     - modules/user-guide/nav.adoc
   ```

   `name` — идентификатор компонента.
   Antora использует его в URL и идентификаторах страниц.

   `title` — название компонента, которое читатели видят на сайте.

   `version` — версия документации, которую описывают эти файлы.
   Заключайте версию в кавычки, чтобы YAML прочитал ее как текст, а не как число.

   `nav` — список файлов навигации компонента; здесь это файл, созданный на шаге 2.

4. Сделайте коммит компонента:

   ```shell
   git add .
   git commit -m "Add the user guide"
   ```

   Ветки версий Antora читает из коммитов, а не из рабочих файлов, поэтому этот коммит обязателен.

Теперь компонент выглядит так:

```
docs-server/
├── antora.yml
└── modules/
    └── user-guide/
        ├── nav.adoc
        └── pages/
            └── index.adoc
```

Файлы `package.json`, `package-lock.json` и `.gitignore` лежат рядом с `antora.yml` в корне репозитория.

## Добавьте плейбук

Контент готов.
Чтобы превратить его в сайт, Antora нужен плейбук.

Версию компонента и сборку сайта определяют два файла конфигурации:

- `antora.yml` — по одному на компонент, в корне репозитория.
  Вы его уже создали.
  В нем заданы имя компонента и его версия.
- `antora-playbook.yml` — плейбук.
  В нем указаны ветки для сборки, UI и настройки сайта.

Разместите плейбук в корне репозитория, рядом с `antora.yml`.

1. Создайте `antora-playbook.yml`:

   ```yaml
   site:
     title: Red Apple Conference Documentation
     start_page: docs-server:user-guide:index.adoc
   content:
     sources:
     - url: .
       branches: [v*]
   ui:
     bundle:
       url: https://gitlab.com/antora/antora-ui-default/-/jobs/artifacts/HEAD/raw/build/ui-bundle.zip?job=bundle-stable
       snapshot: true
   ```

   `url: .` направляет сборку на текущий репозиторий.

   `branches: [v*]` определяет, какие ветки этого репозитория собирает Antora.

   `ui.bundle.url` указывает на стандартный UI Antora, который загружается во время сборки.
   `snapshot: true` сообщает Antora, что бандл по этому адресу меняется со временем.

   `start_page` — идентификатор страницы в Antora: компонент, модуль и страница через двоеточие.
   Сегмент версии в идентификаторе опущен, поэтому Antora берет последнюю версию компонента.

2. Сделайте коммит плейбука:

   ```shell
   git add .
   git commit -m "Add the Antora playbook"
   ```

## Соберите версию 1.0

Antora собирает отдельную версию документации из каждой ветки Git.
Создайте ветку для версии 1.0:

```shell
git branch v1.0
```

Плейбук собирает ветки, которые соответствуют шаблону `v*`, поэтому `v1.0` становится версией 1.0 на сайте.
Ветка `main` остается свободной для работы над следующей версией.

Изменения в `main` не попадут на сайт, пока для них нет ветки `v*`.

Соберите сайт:

```shell
npx antora antora-playbook.yml
```

Antora записывает сайт в директорию `build/site` и выводит сообщение:

```
Site generation complete!
Open file:///.../docs-server/build/site/index.html in a browser to view your site.
```

Откройте `build/site/index.html` в браузере.
Сайт откроется на странице руководства пользователя.
Переключатель версий внизу панели навигации показывает компонент и его версию: **Server 1.0**.
Меню версий вверху страницы пока не отображается: оно появляется, только когда у компонента несколько версий.

## Добавьте вторую версию и пересоберите сайт

Версия 2.0 начинается в ветке `main` — там идет работа над следующей версией.

1. В `antora.yml` измените версию:

   ```yaml
   version: '2.0'
   ```

2. В `modules/user-guide/pages/index.adoc` измените текст страницы, чтобы версии заметно различались:

   ```asciidoc
   = Server User Guide

   This page describes version 2.0 of the server.
   ```

3. Сделайте коммит изменений:

   ```shell
   git add .
   git commit -m "Update the guide for version 2.0"
   ```

4. Создайте ветку версии:

   ```shell
   git branch v2.0
   ```

5. Пересоберите сайт:

   ```shell
   npx antora antora-playbook.yml
   ```

6. Обновите `build/site/index.html` в браузере.

Теперь в переключателе внизу панели навигации есть обе версии, а вверху страницы появилось меню версий.
Переключитесь на 1.0: текст страницы снова описывает версию 1.0.
Эту страницу Antora собрала из ветки `v1.0`.

:::note
Antora читает каждую ветку `v*` из ее последнего коммита, а не из рабочих файлов.
Из рабочих файлов Antora берет только текущую ветку, то есть `main`, а она в сборку не входит.
Нужная ветка версии должна указывать на коммит с вашей правкой.
Если правка не появилась, см. раздел [Устранение неполадок при сборке версий](#troubleshoot-a-versioned-build).
:::

Вы собрали сайт на Antora: две ветки, две версии документации и переключатель между ними.
На реальной платформе тот же механизм работает в большем масштабе: много репозиториев компонентов, один центральный плейбук и автоматизация, которая выбирает ветки `v*` для сборки.

## Устранение неполадок при сборке версий {#troubleshoot-a-versioned-build}

Если собранный сайт выглядит не так, как вы ожидали, сначала проверьте ветки и коммиты в Git.

### Версии нет в переключателе

Плейбук собирает только ветки, которые соответствуют фильтру `branches: [v*]`.
Выведите список таких веток:

```shell
git branch --list "v*"
```

```
  v1.0
  v2.0
```

Если ветка есть в списке, проверьте файл `antora.yml` в этой ветке.
В переключателе отображается значение `version`, а не имя ветки.
Файл из любой ветки можно прочитать, не переключаясь на нее:

```shell
git show v1.0:antora.yml
```

### Правка не отображается на странице

Скорее всего, в ветке версии нет этой правки.
Выведите страницу в том виде, в каком ее читает Antora:

```shell
git show v1.0:modules/user-guide/pages/index.adoc
```

Если правки в выводе нет, сделайте коммит в ветку версии и пересоберите сайт.
